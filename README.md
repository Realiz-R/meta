# meta

> Быстрый просмотр метаданных файлов на Rust — альтернатива ExifTool для повседневных задач.

![Rust](https://img.shields.io/badge/rust-1.75%2B-orange)
![License](https://img.shields.io/badge/license-MIT-blue)
![Platform](https://img.shields.io/badge/platform-Windows%20%7C%20Linux%20%7C%20macOS-lightgrey)

`meta` — нативная утилита командной строки для чтения метаданных из файлов любого типа: файловая система, EXIF, IPTC, XMP, аудио-теги, видео-контейнеры. Один бинарник без зависимостей, работает быстро и выводит данные в удобном для человека виде.

## ✨ Возможности

- **Метаданные файловой системы** — размер, права, временные метки, inode, владелец.
- **Определение типа** — MIME и расширение по magic bytes.
- **EXIF** — с группировкой по категориям (Камера, Экспозиция, Даты, GPS, Изображение).
- **Человекочитаемые значения** — `1/1500 с` вместо `1/1500`, `f/2.0` вместо `2/1`, `55° 45′ 21.00″ N` вместо `55/1 45/1 2100/100`.
- **Расшифровка кодов** — `Flash: 16` → `не сработала, режим подавления`, `MeteringMode: 2` → `Центровзвешенный`.
- **Нормализация дат** — `2026:09:05` → `2026-09-05`.
- **IPTC / XMP** — извлечение через `revelo`.
- **Аудио-теги** — ID3, Vorbis Comment, APE, FLAC через `lofty`.
- **Видео** — контейнеры и кодеки через `revelo`.
- **Форматы вывода** — текст, JSON, CSV.
- **Рекурсивный обход** каталогов с фильтрами.
- **Работа на Windows, Linux и macOS** без внешних зависимостей.

## 🚀 Как это работает

`meta` собирает метаданные из нескольких независимых источников и объединяет их в единый отчёт:

1. **Файловая система** — через `std::fs::Metadata` (размер, права, временные метки). На Unix дополнительно inode, ссылки, UID/GID; на Windows — атрибуты NTFS.
2. **Тип файла** — крейт `infer` читает первые байты и определяет MIME по magic bytes.
3. **EXIF / IPTC / XMP** — основной движок `revelo` (порт MediaInfo на Rust) плюс fallback на `kamadak-exif` и `nom-exif` для форматов, которые `revelo` не покрывает.
4. **Аудио-теги** — крейт `lofty` (ID3v2, Vorbis Comment, APE, MP4 atoms, FLAC).
5. **Видео-контейнеры** — снова `revelo`: длительность, кодеки, битрейт, потоки.

Каждый источник возвращает список пар «ключ → значение». Далее значения проходят через конвейер обработки:

- **Фильтрация** — скрываются служебные теги (байтовые смещения, `MakerNote`) и дубликаты (например, `Encoded_Hardware_CompanyName` при наличии `Make`).
- **Humanize** — дроби превращаются в десятичные (`6830/1000` → `6.8 мм`), коды — в строки (`Flash: 16` → `не сработала, режим подавления`), даты нормализуются в ISO-формат.
- **Группировка** — теги раскладываются по категориям: Камера, Экспозиция, Даты, GPS, Изображение, Прочее.
- **Дедупликация** — финальная проверка по кортежу `(метка, значение, категория)`.
- **Вывод** — в текстовом, JSON или CSV формате.

JSON-вывод всегда содержит **полный набор** тегов (без фильтрации), плюс отдельный блок `exif_display` с человекочитаемой версией — так скрипты не теряют данные, а человек видит удобный отчёт.

## 🎯 Применение

- **Разработка и отладка** — быстрая проверка метаданных изображений, аудио и видео.
- **Медиа-пайплайны** — извлечение тегов в JSON/CSV для последующей обработки.
- **Управление медиатекой** — массовое извлечение тегов из фото и музыки.
- **Форензика и CTF** — базовый анализ метаданных (но помните: не замена ExifTool).
- **Проверка подлинности фото** — расхождение дат, несоответствие `Make` и `Model`, признаки редактирования.
- **Извлечение GPS-координат** — геолокация снимков в человекочитаемом виде.

## 🚩 Флаги

### Что показывать

| Флаг | Описание |
|------|----------|
| `-a, --all` | Показывать все теги, включая служебные и MakerNotes |
| `--short` | Только ключевые теги (Make, Model, ISO, ExposureTime…) |
| `-b, --brief` | Скрыть пустые значения |
| `--no-empty` | Скрыть пустые значения (альтернатива `--brief`) |
| `-G, --groups fs,exif,audio,video` | Показать только выбранные секции |
| `-T, --tags Make,Model,ISO` | Фильтр по машинным именам тегов |
| `--exif-category GPS,Экспозиция` | Фильтр по категориям EXIF |

### Формат вывода

| Флаг | Описание |
|------|----------|
| `--json` | JSON-вывод со всеми полями без потерь |
| `--csv` | CSV-вывод (`path,group,tag,value`) |
| `--raw` | Сырые значения без humanize |
| `--no-color` | Отключить цветной вывод (уважает `NO_COLOR`) |
| `-q, --quiet` | Только значения, без меток и заголовков |
| `--bytes` | Размер в байтах без форматирования |
| `-o, --output FILE` | Записать результат в файл |

### Обход файлов

| Флаг | Описание |
|------|----------|
| `-r, --recursive` | Рекурсивный обход каталогов |
| `--max-depth N` | Ограничить глубину рекурсии |
| `--no-follow` | Не следовать по символическим ссылкам |

### Служебные

| Флаг | Описание |
|------|----------|
| `-h, --help` | Справка |
| `-V, --version` | Версия |

## 📋 Примеры

### Базовый вызов

```bash
meta photo.jpg
```

### Только GPS и экспозиция

```bash
meta --exif-category GPS,Экспозиция photo.jpg
```

### Ключевые теги камеры

```bash
meta --short photo.jpg
```

### JSON для пайплайна

```bash
meta --json photo.jpg | jq '.exif_display'
```

### CSV по всему каталогу

```bash
meta --csv -r ~/photos > all_metadata.csv
```

### Рекурсивный обход с записью в файл

```bash
meta --json -r -o report.json /media/library/
```

### Фильтр по конкретным тегам

```bash
meta -T Make,Model,ISOSpeed --json photo.jpg
```

### Все теги, включая служебные

```bash
meta --all photo.jpg
```

## 🔍 Чем отличается от ExifTool

`meta` **не является заменой** ExifTool и не пытается ей быть.

**ExifTool** — это эталонный инструмент с 20-летней историей:
- ~29 000 тегов, ~18 000 уникальных имён.
- Чтение **и запись** метаданных.
- Полная поддержка MakerNotes всех производителей.
- Все нестандартные форматы: Photoshop IRB, ICC Profile, C2PA JUMBF.

**`meta`** — это быстрый и удобный просмотрщик:
- ✅ Нативный бинарник, ~10× быстрее на пакетной обработке.
- ✅ Нет зависимостей (никакого Perl и CPAN).
- ✅ Человекочитаемый вывод с группировкой и переводом кодов.
- ✅ Легко встраивается как библиотека в другие Rust-проекты.
- ❌ Только чтение, без записи.
- ❌ Меньше покрытие редких тегов и MakerNotes.
- ❌ XMP может быть неполным.

**Используйте `meta`, когда нужен быстрый обзор и удобный вывод.**  
**Используйте ExifTool, когда нужна максимальная полнота данных.**

## 🧩 Технологии

Проект использует специализированные крейты для каждого типа данных:

| Крейт | Назначение |
|-------|------------|
| [`revelo`](https://crates.io/crates/revelo) | Порт MediaInfo: 180+ форматов медиа, EXIF, IPTC, XMP |
| [`kamadak-exif`](https://crates.io/crates/kamadak-exif) | Чистый парсер EXIF на Rust |
| [`nom-exif`](https://crates.io/crates/nom-exif) | Универсальный парсер EXIF для изображений и видео |
| [`lofty`](https://crates.io/crates/lofty) | Аудио-теги: ID3v2, Vorbis, APE, MP4 atoms, FLAC |
| [`infer`](https://crates.io/crates/infer) | Определение типа по magic bytes |
| [`walkdir`](https://crates.io/crates/walkdir) | Рекурсивный обход каталогов |
| [`clap`](https://crates.io/crates/clap) | Парсинг аргументов командной строки |
